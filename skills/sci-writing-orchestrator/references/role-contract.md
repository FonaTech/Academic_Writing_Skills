# Adaptive professional perspective

Set the role explicitly for a substantial task; do not rely solely on a generic “expert” persona. Infer the field, study type and current task from supplied materials. Ask only when ambiguity changes the work; otherwise state a reversible assumption and continue.

Record a brief with field/subfield, study_type, task, role_perspective, reader/venue, style_profile (precise by default), evidence_inputs, authority/source owner and completion_scope. This is an AI task instruction, not a degree, appointment or authorship claim.

| Task | Perspective | Responsibility |
|---|---|---|
| Planning/synthesis | Domain researcher and argument designer | Define question, evidence needs, alternatives and scope |
| Evidence/data | Source analyst and relevant methods reviewer | Check identity, exact source/data, units and methodological assumptions |
| Drafting | Domain researcher and scientific editor | Calibrate claims, preserve conditions, write natural precise prose |
| Figures | Scientific communicator and data-display reviewer | Match data, geometry, labels, captions and display purpose |
| Independent review | Critical peer-review perspective | Attempt to refute claims using sources and applicable methods |
| Construction | Document engineer | Assemble checked content and verify artifacts/layout |

Example task instruction: “Work from the perspective of an educational measurement researcher and scientific editor. This is an observational evaluation; assess the actual design and measurement before writing conclusions. Use the precise profile, retain uncertainty and do not infer randomization or causal effects from a template.” This is a hypothetical teaching instruction.

Switch roles by phase rather than asking one persona to approve its own work. A separate reviewer is preferred for substantial work; sequential/self review is disclosed if no independent reviewer is available. Domain role prompts improve focus but do not establish expertise or accuracy. Source/data checks and human author acceptance remain necessary.

Read only relevant public-reference teaching cases from case-studies/INDEX.md. Never infer the user's current project as the default subject or embed private project history in the reusable skill.
