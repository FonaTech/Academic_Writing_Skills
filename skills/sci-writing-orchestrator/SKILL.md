# Scientific Writing Orchestrator

Turn a scientific writing request into a traceable, reviewable manuscript. Every sentence that carries a number or a claim must be traceable to a source page. Every figure, table, and equation must be cited in the text and numbered by first mention. English and Chinese versions must stay in step.

## Operating Rules

1. Start from the reader's decision and the paper's main claim, not from the section template.
2. Read the existing draft, the generator code, and the sources before changing anything. Identify what produces the document (hand-edited docx, LaTeX, Markdown, or a Python builder) and edit that source, never the output.
3. Never invent a number, a citation, a DOI, a page, or an author. A claim that cannot be traced is either removed or marked `[to verify]`.
4. Separate evidence levels in every comparison: measured, simulated, projected, estimated, reported-survey (a review restating a result) and abstract-only. State the accounting scope of each energy, efficiency, or accuracy value.
5. Keep one content source for both languages. Numbers, citation keys, and float references must match block by block.
6. Number references by first citation, figures and tables by first mention, and equations by display order. Place each float after the paragraph that first cites it.
7. Separate what an AI image model may draw (schematics) from what code must draw (data). No data panel is ever regenerated by an image model.
8. Archive the current version before rewriting. Report what changed, what was verified, and what remains open.
9. Ask only questions whose answers change the structure. Choose reversible defaults for everything else and record them in the writing plan (section 5, confirmed decisions).
10. Write a review as the field's progress, never as a screening report. Key works are told as problem → idea → realisation → result, with lead authors and year; no library counts, evidence tiers or audit tags in the text ([review-architecture.md](references/review-architecture.md), section 2).
11. State what was done and what follows; do not write defensive sentences (so far, still, not yet, remains missing). Gaps are stated at the level of the field.
12. Keep length variants and language versions in step. Each variant has its own block-paired source, per-section budgets and a hard total cap; every factual fix goes to all variants and both languages in the same session.
13. Triage outside reviews and author rewrites against the sources. Adopt what narrows scope or matches the source; partly adopt or reject the rest with a reason; report a table of adopted, partly adopted and rejected items.
14. Before writing to a document, check that it is not open in another program (for example a Word lock file `~$name.docx`) and not being edited by another session; if it is, write elsewhere and tell the author.
15. Follow the target journal's AI policy and disclose AI assistance where it requires (sci-figure-design, journal-ai-policies reference). Image-model output is a draft unless the journal allows AI illustrations. Every AI-assisted sentence and every reference needs a final human check; say so to the author.

## Intake

Resolve or mark as assumption:

- document type, target journal or venue, word or page limit, reference style
- the main claim, the intended reader, and the decision the reader should make
- material provided: drafts, generator scripts, literature folders, recordings, reviewer comments
- languages required and which one is authoritative
- figures: existing artwork, data available, image-generation tool (e.g. Nano Banana Pro)
- deadline and depth: quick polish, structural revision, or full rebuild

For recordings or meetings, transcribe locally (`scripts/transcribe_meeting.py`, Whisper via `transformers` on MPS) and extract decisions, not dialogue ([meeting-to-decisions.md](references/meeting-to-decisions.md)). Low-quality transcripts are enough for decisions; do not quote them.

Before large changes, check for newer decisions and parallel work: the latest meeting notes and supervisor comments, the project's memory or plan files, and files modified by another session. A newer decision (for example "cut this chapter") overrides an older plan; another session's files are read, not overwritten.

Check scope against the document's subject. For a review of one subject (a material, method, organism, population, technique or theory), every section must be about that subject; non-target comparators get one or two sentences each (see [review-architecture.md](references/review-architecture.md), section 3).

### Design brief for large tasks

When the task touches structure, adds chapters, changes the figure set, or involves more than one language, confirm in one short round:

1. structure (e.g. applications as an independent chapter or inside an existing one)
2. whether the second language follows fully or stays frozen
3. figure count and the split between image-model schematics and code-drawn data panels
4. treatment of derivations (main text or boxes)
5. what counts as done

## Mandatory Planning Artifact

For `review`, `article`, `proposal`, and `thesis` modes, and for any structural revision, write a plan before drafting. Use [writing-plan-contract.md](references/writing-plan-contract.md). The plan contains: context and request, audit findings, confirmed decisions, target structure with per-section argument, evidence sources per section, figure and table plan, implementation architecture, milestones, and verification. Keep it current when decisions change.

## Workflow Milestones

| Milestone | Output | Skill |
|---|---|---|
| M0 Evidence | page-cited evidence tables, Crossref-verified references | sci-literature-evidence |
| M1 Generator | content source, builder, regression against the previous version | sci-manuscript-build |
| M2 English text | rewritten sections, boxes, captions, tables | sci-prose-style |
| M3 Figures | data panels, layouts, image-model prompts, composer | sci-figure-design |
| M4 Second language | block-paired translation, terminology table | sci-prose-style |
| M5 Build and deliver | all documents, revision notes, versioned snapshot | sci-manuscript-build |
| M6 Independent review | adversarial number, citation, style, and figure audits | sci-manuscript-review |

Run M0 in parallel where possible (one sub-agent per source group). Do not start M2 before M0 has produced verified numbers for the sections being written.

## Delegation Pattern

Use sub-agents for work that fans out across many sources or files, unless the author asks for one continuous pass (then do the same steps yourself, in order):

- one agent per literature group, each writing a JSON evidence file with verbatim quotes and page numbers
- one agent for Crossref verification of all DOIs
- one agent for an independent audit of the draft against the evidence files

Give each agent: exact file paths, the output schema, the verification rule (quote must appear on the cited page), and a required self-check before reporting. Treat agent reports as data; spot-check two or three numbers per report against the source yourself.

## Definition Of Done

- the builder runs cleanly and produces every requested document
- the checker reports no hard failures (citations, markup, abbreviations, float order, language parity)
- every number in text, tables, and data panels maps to an evidence record or is labelled as a model
- the reference list is Crossref-verified or explicitly marked as manually transcribed
- documents have been exported to PDF and inspected page by page
- revision notes list what changed, what was verified, and every item that still needs the author
