# Response to reviewers and cover letters

## Response letter structure
1. Opening paragraph: thank the editor and referees in one sentence; summarise the main changes in three to five bullet points.
2. For each referee, each comment:
   - **Comment R1.3** (quoted verbatim, italic or indented)
   - **Response.** Answer the point directly in the first sentence. Give the evidence or the new analysis.
   - **Change.** What changed and where: "Section 4.2, paragraph 3 (page 7, lines 12–20); new Fig. 3d; Table 2, new column 'Scope'." Quote the new text when it is short.
3. Closing: one sentence.

## Tone
- Direct and courteous. No flattery ("We thank the reviewer for this insightful comment" once at most, not for every point).
- When the referee is right, say so and fix it. When the referee is partly right, state which part and why.
- When you disagree, give evidence, cite sources, and still improve the text so the misunderstanding cannot recur.
- Never promise a change that is not in the revised manuscript. Check every "we have added" against the new version.

## Common moves
| Situation | Move |
|---|---|
| request for an experiment you cannot do | explain why, give the closest available evidence, add a limitation sentence |
| request to cite the referee's own work | cite if relevant; otherwise explain the scope politely |
| misunderstanding caused by unclear text | thank, clarify in the response, rewrite the text |
| conflicting referee requests | state the conflict and the choice made, with the reason |
| request beyond scope | agree it is interesting, add one sentence to the outlook, explain the scope |

## Triage of external reviews and author rewrites
Use the same procedure for journal referees, a colleague's critique, an AI-generated review, or an author's own rewrite of a section:
1. Split the input into atomic points (one change each).
2. Check each point against the sources before deciding. A suggested wording is adopted only when the cited paper supports it; a suggestion that narrows scope or matches the source wording is usually right.
3. Decide per point: **adopted**, **partly adopted** (say which part), or **rejected** (with the source page or rule that decides it).
4. Record the decision in a table: point, location, decision, reason, change made (block ids, variants, languages).
5. For an author rewrite, keep its structure and voice where it improves the text (topic sentences, named actors, causal bridges), and correct only facts, dropped quantifiers, added motives and arithmetic.
6. Apply adopted points in every variant and both languages in one pass; report the table with the delivery.

| Point | Location | Decision | Reason | Change |
|---|---|---|---|---|
| "say X retains a state rather than persists" | s2.1-a | adopted | matches source wording, p. 3 | s2.1-a EN/ZH, all variants |
| "add ratio to competing method" | s3.2-c | rejected | values have different accounting scopes | scope of each value stated instead |

## Cover letter (submission)
One page: the question and why it matters now; the main finding or the scope of the review with its distinctive angle; why this journal's readers; suggested and excluded referees if allowed; statements required by the journal (originality, competing interests, data availability, use of AI tools and AI-generated images).
