# Planning the figure set

This guide covers what each figure argues, which figure types exist and who draws them, how many figures and tables a paper carries, and when a box is worth its space. It applies to any field. Examples use placeholders (⟨subject⟩, ⟨metric⟩, ⟨finding⟩).

## 1 Figure policy and figure types

Data panels always come from code, drawn from a JSON file in which every value has a source, page and evidence level. No data panel is ever regenerated by an image model. By default (route D), image-model output is a draft that the author redraws in standard software. An AI-drawn panel stays in a final figure only when the journal allows AI illustrations, and then the caption discloses it (journal-ai-policies.md).

| Type | Typical use | Drawn by |
|---|---|---|
| Concept or overview map | opening figure of a review; application map | image-model draft, redrawn by the author (route D); labels ≤ 8 per sector |
| Structure or mechanism schematic | how a system, organism, molecule, device or model is built and works | image-model draft, redrawn by the author (route D) |
| Pipeline, workflow or architecture | stages of a process, a method or a system | image-model draft or diagram code, redrawn by the author |
| Benchmark map | reported values from many papers | code, every point sourced, evidence level visible |
| Model curve | scaling laws, error budgets, dose–response, sensitivity | code, marked "model" |
| Distribution or time trace | statistics, retention, kinetics, time series | code (reproduced from data) or adapted with permission |
| Photograph, micrograph or field image | real samples, sites, specimens | original source with permission; never an image model |
| Map or geographic panel | spatial data | GIS or plotting code from sourced data |
| Table | benchmarks, design rules, cohort characteristics | builder, three-line style |

## 2 Figure budget

Take the binding limits from the target journal's author guide and two or three recent papers of the same type in that journal. Typical planning targets:

| Document | Figures | Tables | Boxes |
|---|---|---|---|
| Full review, 8–12k words | 8–14 (about one per 800–1,000 words) | 2–4 | 0–4 |
| Review chapter set inside a longer review | one per major section plus one overview | 1 per major section | as needed for derivations |
| Perspective, 4–6k words | 3–5 | 1–2 | 0–2 |
| Research article, Nature-family | 4–6 main (≤ 6 panels each), extended data as needed | 0–2 | 0 |
| Letter / communication | 3–4 | 0–1 | 0 |
| Thesis chapter | one per main claim | as needed | optional |

In length variants of one manuscript (for example 25%, 50% and 100%), keep the same figure set where the budget allows and the full comparison tables in every variant; shorten prose, not evidence.

## 3 Rules

1. **Write each figure's argument as one sentence before drawing anything.** State a finding ("⟨Factor⟩ sets most of the ⟨cost⟩ of ⟨process⟩"), not a topic ("⟨Process⟩ overview"). The caption title then names the object and measurement ([captions-and-tables.md](captions-and-tables.md), rule 3).
2. **Budget figures by genre.** Articles carry four to six main figures and move controls, repeats and literature benchmarks to the Supplementary Information (SI); reviews carry seven to fourteen.
3. **Make figure order the argument order.** First citations ascend, panels are cited alphabetically and every main figure is cited. Place each figure after the paragraph that first cites it.
4. **Open a review with an original overview figure, and build its sections on synthesis figures.** A collage of one panel per paper does not count. A synthesis figure is a schematic that argues the mechanism or a benchmark map of many works.
5. **Plan the tables with the figures.** A comparative review needs at least one metric benchmark table in the main text. A free-text table of pros and cons does not count, and no panel duplicates a table.
6. **Trace every point of a benchmark map to a sourced record.** Each value carries source, page, evidence level and scope in `panel_data.json`. Fix the population, sources, cut-off date and normalisation before plotting, and state them in the caption. Never plot values of different accounting scopes on one axis without marking the scope.
7. **In a mixed figure, put schematics on top and data below.** Readers need the concept before the evidence, and data panels in a row share one height.
8. **Use one evidence code across the manuscript.** Filled marks show measured values; open or hatched marks show simulated, projected or abstract-only values; grey shows non-target comparators; a bare line shows a model. Explain the code once in the first caption that uses it, then repeat the short form.
9. **Use a box only for a self-contained side argument, cited at the claim it supports.** Typical content is a calculation with its assumptions, or a metric definition.
10. **Decide the licence route of every reused panel while planning.** Record CC BY, RightsLink permission or a redraw in `sources.csv` before the layout. When adapting is not possible, a schematic row plus a code-drawn benchmark row gives the same density of evidence.
11. **Check author-supplied artwork after any renumbering.** Reference numbers or figure numbers baked into a figure's labels go stale when citations are renumbered; list them and ask the author to update the artwork.

## 4 Templates

```
Figure plan (one block per figure)
  Argument   one sentence that states the finding
  Placement  the paragraph that first cites the figure
  Panels     a | schematic | what it proves    b | data | what it proves | evidence level, scope
  Sources    panel_data.json records; reused panels with DOI, licence route and credit line
  Size       print width 180 mm (double column) or 88 mm (single), grid, aspect ratio

Box N | [The question it answers]
  2-4 short paragraphs: the calculation or definition, its assumptions, one sourced number.
  Cited in the text as "(Box N)", for example "Box 1 | What a ⟨metric⟩ figure includes".
```

## 5 Anti-patterns and fixes

| Pattern | Problem | Fix |
|---|---|---|
| Collage-led review | each section reprints one panel per paper, narrated panel by panel | one synthesis schematic per section plus a code-drawn benchmark row |
| Topic as argument | figure titled "⟨Topic⟩ overview" | a finding sentence that the panels prove |
| Unmarked evidence levels | simulated and measured points share one marker | the manuscript-wide evidence code |
| Mixed scopes on one axis | component-level and system-level values plotted together | separate panels, or markers by scope with the scope named in the caption |
| Image-model data | an AI-drawn chart with invented values | code-drawn panel from sourced JSON |
| Stale baked-in labels | "[23]" printed inside author artwork after renumbering | list and ask the author to update |

## 6 Venue differences

Nature-family journals cap article figures (usually 4–6 main figures, Extended Data up to 10) and require source data. Cell Press journals require a graphical abstract. Society journals vary; check the author guide for colour charges, figure counts and TOC graphics. Engineering conferences cap pages, so figures compete with text.

## 7 Checks before rendering

1. Every figure has a one-sentence argument and a first-citing paragraph.
2. Figure count and table count fit the venue and the genre.
3. Every data point traces to a sourced record with evidence level and scope.
4. Every reused panel has a licence route and a credit line.
5. Schematics are image-model drafts redrawn by the author unless the journal allows AI illustrations.
6. Baked-in labels in author artwork match the current numbering.
